# バンド削除API

## 概要

管理画面からバンド本体を削除する実装済みAPI。公開フォームのメンバー所属解除とは別の操作で、確認ダイアログで確定した場合だけ呼ぶ。

## API仕様

| 項目                   | 内容                                                                     |
| ---------------------- | ------------------------------------------------------------------------ |
| エンドポイント         | `/api/events/{eventId}/bands/{bandId}`                                   |
| HTTPメソッド           | DELETE                                                                   |
| 呼出し元 → 呼出し先    | ブラウザ → backend                                                       |
| リクエスト・レスポンス | application/json                                                         |
| 所有者                 | 認証接続前は既存管理APIと同じ仮所有者 `demo-owner`。未削除イベントに限定 |

バンド本体・希望原文・対象バンドの所属・配置を削除し、他バンドの`order`は変更せず、空いた位置を未設定のまま残す。メンバー名簿、他バンドの所属、部、制約、会話は保持する。最後のバンドも削除できる。

制約の対象または`sourceBandId`に参照されるバンドは、有効／無効・必須／任意を問わず削除しない。削除後のバンド数で位置指定・位置範囲が範囲外になる場合も拒否する。先に制約一覧で編集・削除する。残る制約を勝手に変更・緩和せず、出演順が詰まることで生じる達成状況の変化は管理画面で再評価する。

## リクエスト

```http
DELETE /api/events/event-1/bands/band-1
Content-Type: application/json
```

```json
{ "expectedUpdatedAt": "2026-10-18T00:00:00.000Z" }
```

`expectedUpdatedAt`は確認対象の名簿を取得したときの`updatedAt`。必須のISO日時で、未知のフィールドは受け付けない。確認後に別の保存が入った場合は409で何も削除しない。最新の日時を裏で取り直して競合を回避しない。

## レスポンス

成功はHTTP 200。

```json
{
  "eventId": "event-1",
  "bandId": "band-1",
  "updatedAt": "2026-10-18T00:01:00.000Z"
}
```

返却した更新日時は前回より進む。削除・所属・対象の配置・更新日時は同じD1 batchで確定し、途中で失敗した場合は全て取り消す。同じ更新日時での同時削除は片方だけ成功する。

| HTTP | code                     | 条件                                           |
| ---- | ------------------------ | ---------------------------------------------- |
| 400  | invalid_input            | 不正なJSON                                     |
| 404  | event_not_found          | 存在しない・別所有者・削除済みイベント         |
| 404  | band_not_found           | このイベントに対象バンドがない                 |
| 409  | event_save_conflict      | 確認元のデータが古い                           |
| 409  | band_constraint_conflict | 制約の対象・生成元・削除後の位置範囲に影響する |
| 422  | invalid_input            | 更新日時なし・不正日時・未知のフィールド       |
| 500  | internal_error           | DB等の内部失敗。部分削除しない                 |

制約参照のエラー例。`details`には先に整理する制約IDを含める。

```json
{
  "error": {
    "code": "band_constraint_conflict",
    "message": "制約から参照されています。制約一覧で対象・生成元・位置範囲を確認し、先に制約を変更・削除してください。",
    "details": [
      {
        "path": "/constraints/constraint-1",
        "reason": "このバンドまたは削除後の位置範囲を参照する制約を先に変更・削除してください。"
      }
    ]
  }
}
```

## 懸念点・未決定事項

メンバー本体の削除、バンドの復元、削除に伴う制約の自動削除・自動緩和は対象外。認証接続時は既存管理APIと同様に、Routeで渡す仮所有者を認証済みIDへ置き換える。
