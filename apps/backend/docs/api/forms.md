# フォーム名簿API

## 概要

ブラウザの出演登録フォーム → backendのAPI定義。イベントへバンドとメンバーを登録し、バンドを選んで所属メンバーを追加・差し替え・解除する。名簿の登録・差し替え・所属解除を実装済み。フォームURLを知る人が認証なしで取得・登録・編集できる。新規登録は1人以上、編集では全員の所属解除を許可する。

合意済みの編集操作は、**そのバンドのメンバーを別の人へ差し替えること**。メンバーの名前を変更して全所属バンドへ反映するAPIは設けない。既存メンバーを選ぶ場合はIDを使い、新しい人なら新規登録する。

**「削除」は選択したバンドからの所属解除とする。** Memberレコードはイベント名簿に残し、他バンドへの所属の有無にかかわらず、フォームのメンバー選択候補として取得・再選択できる。例えば田中がA・Bに所属するとき、Aから外してもBの所属は維持する。公開フォームではバンド・メンバー本体の削除を提供しない。バンド本体の削除は[管理用バンド削除API](bands.md)を使う。[既存DB方針](../../../../docs/database.md#部と制約の動作)と同じ扱いとする。

`routes/form.ts` → `services/form` → `repositories/form.ts`で処理する。名簿処理は#16の管理者向けAPIからも再利用できる。今回の範囲は#58・#46に関係する名簿操作で、フォーム設定・回答確認・希望文の変換は含めない。画面接続は#59で扱う。希望原文・制約化は[AIチャット設計](../AIチャット設計.md)の別処理とし、以下の名簿操作では既存の希望・制約・配置を変更せず、Solverも起動しない。

## API仕様

共通パスは`/api/events/{eventId}`。

| メソッド | エンドポイント                              | 用途                                                     | 成功時 |
| -------- | ------------------------------------------- | -------------------------------------------------------- | ------ |
| GET      | `/api/events/{eventId}/form`                | 選択用のバンド・メンバー・所属を取得                     | 200    |
| POST     | `/api/events/{eventId}/form/bands`          | バンドと所属メンバーを登録                               | 201    |
| PATCH    | `/api/events/{eventId}/form/bands/{bandId}` | バンド名と所属メンバーを変更。追加・差し替え・解除を含む | 200    |

- 入出力は`application/json`。送信・保存ボタンで保存する。
- 認証なし。イベントIDを含むフォームURLを知る人は、そのイベントの名簿取得・バンド登録・全バンドの名称／所属編集ができる。管理用の仮所有者`demo-owner`や所有者限定のServiceは使わない。管理者向けAPIの認証・所有者確認とは独立する。
- GETは選択に必要なID・名前・所属だけを返す。希望原文・連絡先・回答一覧・制約・チャット・所有者情報は返さない。
- フォーム設定・回答確認・件数・受付終了は今回の対象外。現在は有効なイベントで常時受付し、削除済みイベントは取得・登録・編集できない。受付状態・締切による終了を追加する場合は#33・#58で条件を決め、保存時の判定も同時に実装する。
- IDは文字列。既存IDをUUIDに限定せず、新しいBand・MemberのIDはbackendで発行する。

### 保存の共通ルール

- 全更新で取得時の`updatedAt`を`expectedUpdatedAt`として送る。UTCのISO 8601文字列で、最新でなければ409として全体を保存しない。
- 1リクエスト内のBand・Member・所属・Event.updatedAtを同じD1 batchで保存する。途中失敗で新規メンバーだけを残さない。
- 保存時にイベントの存在・削除状態・対象バンドの所属先・更新日時を再確認する。更新日時は以前より必ず1ミリ秒以上進める。
- 同じ人は同じ`memberId`で識別する。同名でも新規登録なら別人。同名の既存メンバーへ自動統合しない。
- バンド登録直後は未配置。所属変更による制約違反は再評価・表示し、制約や配置を自動変更しない。

## リクエスト

### 選択用名簿の取得

ボディなし。

```http
GET /api/events/event-1/form
```

### バンドとメンバーの登録

既存の田中を選び、新しいメンバーの鈴木を同時に追加する例。

```http
POST /api/events/event-1/form/bands
Content-Type: application/json
```

```json
{
  "expectedUpdatedAt": "2026-10-17T00:00:00.000Z",
  "bandName": "バンドA",
  "memberIds": ["member-1"],
  "newMembers": [{ "memberName": "鈴木" }]
}
```

`description`（バンド紹介）以外は必須。使わない配列は空配列にする。希望原文・変換状態はともに`null`で開始する。`description`はジャンル・雰囲気などの紹介で、AIの並べ替え案に使う。500文字まで、省略・空文字・`null`は紹介なし。

### バンドの編集・メンバーの追加・差し替え・所属解除

バンドAの所属を「田中・鈴木」から「田中・佐藤」にする例。鈴木を外し、佐藤を新しく登録して追加する。鈴木の他バンドへの所属は変えない。

```http
PATCH /api/events/event-1/form/bands/band-1
Content-Type: application/json
```

```json
{
  "expectedUpdatedAt": "2026-10-17T00:01:00.000Z",
  "memberIds": ["member-1"],
  "newMembers": [{ "memberName": "佐藤" }]
}
```

- `bandName`・`description`・所属のいずれかを指定する。省略した項目は保持する。`description`は空文字・`null`で消去する。
- 所属を変える場合は`memberIds`と`newMembers`を両方指定する。保存後の所属全体を渡す。
- 既存の佐藤へ差し替える場合は、佐藤のIDを`memberIds`に含め、`newMembers`は空配列にする。
- 外す人のIDは`memberIds`から除く。追加する既存の人のIDは含める。
- 解除するのは対象バンドとの所属行だけ。名簿、他バンドへの所属、既存制約と配置は保持する。専用のDELETE APIは設けない。
- 編集では`memberIds: []`・`newMembers: []`で全員を外せる。バンド本体は保持し、メンバーも名簿に残す。新規登録時は1人以上を必須とする。
- メンバーの名前そのものを更新するフィールドは受け取らない。別の人への差し替えで同じIDを使い回さない。

田中・鈴木のうち鈴木を外すだけの場合は、田中のIDだけを残す。

```json
{
  "expectedUpdatedAt": "2026-10-17T00:01:00.000Z",
  "memberIds": ["member-1"],
  "newMembers": []
}
```

鈴木の`member-2`はイベント名簿に残る。次のGETでも`members`に含まれ、対象バンドと`member-2`の組だけが`memberships`からなくなる。再追加する場合は`newMembers`で作り直さず、`memberIds`に`member-2`を指定する。

### 入力検証

| 対象           | 検証                                                   |
| -------------- | ------------------------------------------------------ |
| バンド名       | 前後の空白を除去し1〜80文字                            |
| 新規メンバー名 | 前後の空白を除去し1〜40文字                            |
| 所属人数       | 新規登録は1〜20人、所属更新は0〜20人                   |
| 既存メンバーID | 重複不可。同じイベントに存在すること                   |
| PATCH          | 更新項目なし、所属配列の片方だけ、必須値へのnullを拒否 |
| その他         | 未定義項目、所有者・配置・制約等の指定を拒否           |

人数・文字数は現行FEの入力制限を基本とし、編集時だけ0人を許可する。既存DBデータへ遡及して制限せず、バンド名だけの変更では既存所属をそのまま保持する。

## レスポンス

### 選択用名簿

HTTP 200。各配列は空配列も許す。バンド・メンバーは各ID昇順、所属は`bandId`・`memberId`昇順。

```json
{
  "eventId": "event-1",
  "eventTitle": "秋ライブ",
  "updatedAt": "2026-10-17T00:00:00.000Z",
  "bands": [{ "bandId": "band-2", "bandName": "バンドB" }],
  "members": [{ "memberId": "member-1", "memberName": "田中" }],
  "memberships": [{ "bandId": "band-2", "memberId": "member-1" }]
}
```

`bandId`で所属を選び、`memberId`から名前を表示する。同名の場合は所属バンドも表示して識別できる。所属0件のメンバーも候補に含める。所属解除された人を`members`から除外しない。

### 登録・編集の成功

登録は201、編集は200。`members`は保存後にそのバンドへ所属する全メンバーで、新しく発行したIDを含む。

```json
{
  "eventId": "event-1",
  "updatedAt": "2026-10-17T00:02:00.000Z",
  "band": {
    "bandId": "band-1",
    "bandName": "バンドA",
    "memberIds": ["member-1", "member-3"]
  },
  "members": [
    { "memberId": "member-1", "memberName": "田中" },
    { "memberId": "member-3", "memberName": "佐藤" }
  ]
}
```

次の更新には応答の`updatedAt`を使う。フォームはGETで再取得し、管理画面では`GET /api/events/{eventId}/schedule`でも最新の名簿を確認できる。

### エラー

既存イベントAPIと同じ`error.code`・`message`・`details`形式。公開APIなので401・403は返さず、受付終了の409も未導入。

| HTTP | code                  | 場面                                             |
| ---- | --------------------- | ------------------------------------------------ |
| 400  | `invalid_input`       | 不正なJSON                                       |
| 404  | `event_not_found`     | イベントが存在しない・削除済み                   |
| 404  | `band_not_found`      | パスのバンドがこのイベントに存在しない           |
| 409  | `event_save_conflict` | 取得後に業務データが更新された                   |
| 422  | `invalid_input`       | 名前・人数・重複ID・別イベント参照・未定義項目等 |
| 500  | `internal_error`      | 保存失敗。部分保存しない                         |

HTTP 422の例。別イベントの名前や情報は返さない。

```json
{
  "error": {
    "code": "invalid_input",
    "message": "入力データが不正です。",
    "details": [
      {
        "path": "/memberIds/0",
        "reason": "このイベントのメンバーを指定してください。"
      }
    ]
  }
}
```

### 実装時の受け入れ例

| 操作・条件                           | 期待結果                                                  |
| ------------------------------------ | --------------------------------------------------------- |
| Aへ既存m1と新規m2を登録              | Aは未配置。m1の他バンドへの所属は残る                     |
| Aのm2をm3へ差し替え                  | Aの所属だけ変わる。m2の名前・他バンド所属は変わらない     |
| Aからm2を外し、Bにもm2が所属している | Aとm2の所属だけ解除。Bの所属・名簿・制約・配置は保持      |
| Aからm2を外し、m2の所属が0件になる   | m2はGETのmembersに残る。同じIDでAや別バンドへ再追加できる |
| 同名の新規メンバーを追加             | 別IDで登録。既存の人と自動統合しない                      |
| 不正名・重複ID・別イベントのID       | 422。新規メンバーも含め何も保存しない                     |
| 同じupdatedAtで同時保存              | 片方だけ成功し、もう片方は409                             |
| 保存途中のDB失敗                     | 500。Band・Member・所属・更新日時を全てロールバック       |
| 削除済み・存在しないイベント         | 保存処理を進めない                                        |
| 所属変更で制約違反                   | 制約・配置を保持し、違反を再評価・表示                    |

## 懸念点・未決定事項

- **受付終了**：フォーム設定・締切・受付状態を追加する場合は、#33・#58で項目と保存先を合意する。現在はイベントが有効な間、常時受付。
- **通信断後の再送**：POST成功後に応答だけ失われた場合、同じupdatedAtの再送は409。再取得で確認する。登録の重複を明確に識別するキーを設けるかは実装前に決める。
- **希望・連絡先・回答数**：名簿操作だけを理由に回答履歴テーブルや回答数を新設しない。希望原文を同時送信する場合は#46と保存境界を合わせる。

入出力・エラーは`openapi.json`のFormタグ、RPC型は`AppType`と`routes/form.ts`の`FormAppType`で公開する。リクエストテスト・D1結合テスト・契約テストを追加し、未決定事項の機能は今回のAPIへ混ぜない。
