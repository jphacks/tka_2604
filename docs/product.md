# Setly のアプリ仕様

実装に使う合意済み仕様はこのリポジトリで管理する。

## 目的とMVP

掛け持ち出演者のいるライブの運営者が、出演順のたたき台を作って調整できるようにする。Setlyが扱うのはバンド内の曲順ではなく、バンドの出演順。想定は30〜40バンド、各4〜7人。

1. バンド・出演者・部の情報を入力する。
2. 対話で要望を制約化し、GUIで内容・hard/soft・優先度を確認して適用する。
3. ハード制約を守り、ソフト制約をできるだけ満たす出演順を生成する。
4. 達成状況を見ながら、条件変更・手動並べ替え・再生成で調整する。

対話とGUIは同じ制約一覧を使う。条件の変更はユーザーが確認する。「盛り上がる順に」など曖昧な並べ替えの希望は、バンド紹介（Band.description）をもとにLLMが並べ替え案を作る。違反はプログラムで判定し、必須条件に違反する案はSolverで必須条件を満たす一番近い並びに直す。案はユーザーが確認して保存する（#71）。技量の良し悪しをLLMが独自に判断する機能は対象外。

## 画面

- イベント一覧：イベントの選択・作成。
- イベント詳細：出演順、制約一覧、AIチャット。位置固定・手動並べ替えもここで行う。
- 出演枠・メンバー管理、イベント設定、出演登録フォーム、フォーム管理、ワークスペース開始画面。業務データは同じ環境の実API・D1から取得・保存する。公開フォームはURLを知る人がバンド名と所属メンバーを登録・更新できる。認証APIの接続は後続。

## 受け入れ条件

| 場面                   | 期待する動作                                                 |
| ---------------------- | ------------------------------------------------------------ |
| 生成成功               | バンドの欠落・重複がなく、有効なハード制約をすべて満たす     |
| ソフト制約が両立しない | 解を表示し、制約ごとの達成・未達成が分かる                   |
| ハード制約が両立しない | 勝手に緩めず、解なしを伝える                                 |
| 探索未完了             | 解なしと区別。実行可能解があれば最適性未証明として表示できる |
| 手動並べ替え           | 現在の並びの違反を表示。自動修正はユーザーの操作で行う       |

## 未決定

ソフト制約の評価方法、探索時間の上限、再生成時の変更量、入力・保存・認証・出力の詳細。着手するIssueで必要な分だけ決める。詳細な衝突原因の説明、複数ステージ、雰囲気の自動評価はMVPの必須にしない。

## 現在のフロントエンド

- 固定イベント・名簿・メモリ内ストア・モック切替は持たない。DBが空なら空の一覧を表示し、API失敗時はエラーを表示する。再読み込みでサンプルを復元しない。テスト専用の入力例や外部通信の差し替えはアプリの業務データとして使わない。
- 出演登録フォームの初回登録・登録内容の更新は実APIへ保存し、管理画面でも同じ名簿を取得する。希望・連絡先・受付設定・回答履歴の保存、バンド本体の削除は管理画面で確認後に実行する。メンバー名簿と他バンドの所属は残し、制約参照があっても削除でき、削除対象が生成元の制約は一緒に削除し、それ以外の制約は残す。名簿CSV（曲名・紹介・メンバー）を確認後に取り込める。
- 手動追加は6種類の条件から選び、対象・部・位置・数値・強さを入力し、日本語の要約を確認して追加する。自由文を条件として保存したり、チャット送信だけで制約を適用したりしない。
- メンバーはIDで識別する。掛け持ちは登録済みのメンバーを選び、同名の別人は新しいメンバーとして登録する。
- 現在の並びに対して制約ごとの達成・違反を判定する。対象が未配置なら未判定、無効なら判定から除外する。ソフト条件の合計点や優先度によるスコアは算出しない。
- 固定チェックは有効なhardの `at_position` と同じ情報を使う。指定位置に配置されていると固定される。未配置・位置違反の条件を追加しても、勝手に配置を変更しない。
- その他のハード条件に違反する手動配置は警告を表示する。条件を自動で緩めたり、並びを自動修正したりしない。
- 自動生成は計算APIへ接続する。チャットのbackendはLLM呼び出しと会話本文のDB保存へ接続済み。DBイベント・APIキーがあれば返信を表示できる。名簿・出演順・制約を取得し、出演順の明示保存・制約の自動保存と履歴復元に対応する。チャット提案は確認・必要な必須／任意と優先度の選択後に一覧へ反映し、自動保存する。チャットの並べ替え案は確認モーダルで変更後の並び・必須条件の違反・任意条件の増減を表示し、保存を選ぶと出演順を保存、破棄では既存の並びを保持する。計算ボタンは出演順・制約を先に保存してからSolverへ渡し、解なし・探索未完了・失敗では既存配置を保持する。チャットからの計算実行は後続。

操作手順・URL・保存範囲は[フロントエンドの使い方](frontend.md)に記載する。

## 部構成の設定（#91）

作成時と出演順画面の「ライブ情報の編集」で部数・各部のバンド数を数値入力する。設定は保存後も保持し、手動移動・生成結果から自動変更しない。部をまたぐ移動は枠数を維持して順送りし、縮小で収まらないバンドは未配置に戻す。自動生成は設定枠数内で配置する。登録不足時は空き枠、超過時は未配置を許し、生成自体を事前に止めない。
