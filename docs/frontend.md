# フロントエンドのデモ

## 起動と一通りの操作

リポジトリルートで `npm run dev` を実行し、`http://localhost:5173` を開く。

1. 「デモアカウントで試す」からイベント一覧へ入る。実際の認証情報は入力しない。
2. 「春ライブ 2026」を開くか、新しいイベントを作る。
3. 「出演枠・メンバー」から出演枠を追加する。掛け持ちは登録済みのメンバーを選び、新しい人だけ入力する。名簿がある場合は「CSVを取り込む」から「曲名,メンバー1,…」のCSV（UTF-8またはShift_JIS）をまとめて登録できる。形式はダイアログの「雛形をダウンロード」で確認できる。同じ名前は同じ人として扱い、登録済みの人と同じ名前ならその人を使う。同名の登録済みメンバーが複数いる名前は取り込めない。
4. 「出演枠・メンバー」の「回答フォーム」、または「フォーム管理」の「回答フォームを開く」からデモ用フォームを開く。初回登録・更新が同じタブの管理画面名簿へ反映される。フォーム管理の設定・プレビューは引き続きデモ。実APIの公開フォームは別URLで開く（下記「公開フォーム」参照）。
5. 「出演順」で順番号を入力し、Enterまたはフォーカスを外して確定する。空欄で未配置に戻る。「未配置へ」から未配置一覧へ移動できる。
6. 「手動追加」で条件の種類を選び、対象・数値などを入力する。確認欄の日本語と「必須／任意」を確認して追加する。必須は必ず守る条件、任意はできるだけ守る条件で、任意のみ優先度を選べる。チャットを使わずに追加でき、要望の原文も未入力でよい。
7. 並べ替えながら制約ごとの達成・違反・未判定を確認する。「未達成のみ」で違反と入力不備を絞り込める。未判定はこの絞り込みに含めない。
8. 必要なら「CSVを出力」で現在の出演順と未配置一覧を保存する。

サンプルは3部・各4枠、配置済み12組と未配置2組。イベントを削除しても、再読み込みすればサンプルを復元できる。

## URL

イベント詳細はPC（幅1280px以上）で、出演順・制約・右端のAIチャットの3列に表示する。ヘッダー以下の高さを使い、各一覧・チャット履歴は領域内でスクロールする。狭い画面では縦に並ぶ。イベント名は上部ナビゲーションに表示し、チャット入力はチャット領域の下部に置く。

| URL                            | 内容                                         |
| ------------------------------ | -------------------------------------------- |
| `/login`                       | デモ開始                                     |
| `/event`                       | イベント一覧・検索・作成                     |
| `/event/:eventId`              | 出演順・制約・チャット                       |
| `/event/:eventId/performances` | 出演枠・所属メンバー・希望の編集             |
| `/event/:eventId/forms`        | ログイン不要のバンド登録・更新フォーム       |
| `/event/:eventId/forms/demo`   | 同じタブの名簿を使うデモ用登録・更新フォーム |
| `/event/:eventId/forms/edit`   | フォーム設定・プレビュー                     |
| `/event/:eventId/settings`     | イベント設定・削除                           |

サンプルIDは `spring-live-2026`、`autumn-session-2026`、`winter-live-2026`。存在しないイベント・URLには復帰リンクを表示する。

## データと制約の扱い

- 管理画面のデータとログイン状態は、このタブのメモリ内だけに保持する。画面移動では保持し、再読み込みでリセットする。`/forms/demo`の登録・更新もこのメモリ内の名簿を共有する。`/forms`は実API・DBへ接続し、再読込後も名簿が残る。
- 新しいメンバーの区切りは「、」「,」「，」または改行。名前の中の「・」は分割しない。同名でも新しく入力した人は既存の人と統合しない。
- 画面の部・順番号は1始まり、制約データは0始まり。「間に2組空ける」は `min_diff: 3`。間隔は現在の枠番号の差で判定し、空き枠を詰めない。
- 固定は指定位置にある有効なhardの `at_position` から導く。固定チェックを外すと、その出演枠の有効なhardの位置指定を削除する。softの位置指定や無効な条件は固定しない。
- 配置済みの出演枠は、部をまたぐ場合も固定枠を飛ばして並べ替える。移動元から移動先までの固定されていない枠（空き枠を含む）だけが順にずれ、ドラッグ中も固定枠は動かない。固定枠への直接配置は拒否する。未配置から埋まった枠へ移すと、押し出された出演枠が未配置に戻る。
- 「並べ替え」ハンドルにフォーカスし、Spaceで持ち上げ、上下の矢印で移動先を選び、Spaceで確定する。Escapeで取り消す。確定・取消後もハンドルにフォーカスが残る。番号入力でも同じ配置操作ができ、範囲外の入力は確定時に短いエラーを表示する。番号入力もEscapeで入力前の値に戻る。
- 部数は1〜8、各部は1〜20枠。縮小で外れた出演枠は未配置へ移す。固定位置がずれる変更や、制約の位置・部参照が範囲外になる変更は拒否する。無効な条件も参照を保持するため、必要なら先に編集・削除する。
- 制約に直接参照されている出演枠は削除できない。制約一覧で確認・整理してから削除する。メンバー対象の間隔条件は名簿から出演枠を集め直す。
- 達成判定は現在の配置に対するもの。対象に未配置の出演枠があれば未判定、無効なら判定対象外。ソフト条件の重み付きスコア・最適性は扱わない。
- CSVはUTF-8 BOM付き。部・順番号・出演名・メンバー・固定を出力し、未配置も末尾に含める。数式として解釈される先頭文字を含む値は文字列として出力する。

## 未接続の機能

実認証・管理者向け名簿画面とDBの同期・ソルバーには未接続。「自動生成（準備中）」は無効。チャットのbackendは本文保存・LLM生成・回答本文保存へ接続済みで、画面は`reply`を表示する。実際の送信には画面と同じIDのDBイベントとAPIキーが必要。送信中は連打を防止し、失敗時は入力欄へ本文を戻す。画面での履歴復元・再送IDの保持は後続。制約は変更しない。フォーム管理の締切・受付状態・希望・連絡先設定はデモのプレビューだけに適用し、公開フォームAPIへは未接続。

## 確認

```sh
npm run check
npx playwright install chromium # 初回のみ
npm run test:e2e
```

ブラウザテストはポート5174でfrontendを起動し、結果を `apps/frontend/test-results/` に出力する。チャットの応答は成功・失敗ともテストで差し替え、実LLMを呼ばない。通常実行の公開フォームテスト（`members.spec.ts`）はHTTP応答を差し替える。実API・ローカルD1のテストは下記の別コマンドで実行する。ソルバー・本番の認証・本番DBは検証しない。

## イベント画面での出演枠編集

出演順一覧の出演名を押すと、画面を移動せず出演名・所属メンバー・希望・連絡先を編集できる。配置済み・未配置の両方で利用でき、保存しても配置と固定は保持される。名前は制約の要約へ反映され、メンバー変更後は間隔制約を再評価する。キャンセル・閉じるボタン・ダイアログの外側クリックは変更を破棄して元の出演名へフォーカスを戻す。内側から外側へのドラッグでは閉じない。保存中は閉じる操作を受け付けない。

## 公開フォーム（#82）

`/event/:eventId/forms` は公開名簿APIを使い、ログインなしで初回登録と更新を選べる。APIアダプターは `features/forms/repositories/registrationRepository.ts` にまとめ、#59の後続接続からも共用する。管理者向けの全データ取得やモックへのフォールバックは行わない。

ローカルでは[環境構築](setup.md#イベントapiのローカル確認15)に従ってmigration・seedを投入し、backendとfrontendを起動して `http://localhost:5173/event/demo-event/forms` を開く。管理画面の「回答フォーム」リンクとコピー用URLは `/forms/demo` を指し、サンプル・このタブで新規作成したイベントの両方に対応する。デモ用フォームにはデモ表示と再読み込みでリセットされる旨を表示する。`/forms` は実API専用のままで、取得失敗をデモへ自動切替しない。

- 初回登録：バンド名と1〜20人を登録する。「メンバーの行を追加」で1人ずつ名前を入力し、掛け持ちは各行の「名簿から選ぶ」で既存IDを選択する。同名を新しく入力した場合も別IDで登録する。
- 更新：プルダウンからバンドを選び、バンド名と現在の所属を編集する。「削除」はそのバンドとの所属解除。「新しい人を入力して差し替え」や名簿選択で別の人へ差し替えられる。0人での保存も可能で、元の人の名前・他バンド所属は変更しない。
- 保存するまで通信による更新は行わず、モード・バンドの切替で編集中の入力をリセットする。送信中は入力・切替・連打を防止する。
- `expectedUpdatedAt`に取得時の日時を渡す。成功後は保存結果とGETで最新名簿を反映する。409では入力を保持して再取得を案内し、明示的に再取得するまで再送しない。再取得後も入力を保持するため、最新の所属と見比べてから保存する。
- 希望・連絡先・締切・受付設定・回答数は名簿APIに含まれず、公開画面では入力・保存しない。フォーム管理の接続は#59の対象。

実APIの確認には、seed済みのローカルbackend（8787）が必要。テストは専用のイベントを作り、初回登録→再読込→差し替え→全員の所属解除→同じIDで再追加→再読込を確認する。

```sh
FORM_API_E2E=1 npm exec --workspace=@jphack-2026/frontend -- playwright test registration-api.spec.ts
```

`CAPTURE_FORM_SCREENSHOTS=1`も指定すると、実API接続中の[登録画面](screenshots/issue-82/registration.png)・[更新画面](screenshots/issue-82/update.png)を再撮影する。
