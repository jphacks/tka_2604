# フロントエンドの使い方

通常起動・ビルドでは同一originの実APIと、その環境のD1を使う。devとmainのDBはWorkers設定で分離し、固定のイベントを画面内で生成しない。

## 起動と一通りの操作

リポジトリルートで `npm run dev` を実行し、`http://localhost:5173` を開く。

1. 「ワークスペースを開く」からイベント一覧へ入る。
2. 一覧から保存済みイベントを開くか、「イベントを作成」から新しく登録する。
3. 「出演枠・メンバー」の「出演枠を追加」または「回答フォーム」からバンド名とメンバーを登録する。名前は1人1行で人数分を追加し、掛け持ちの人は名簿から選ぶ。同名を新しく入力した人は別IDになる。
4. 「フォーム管理」から回答フォームのURLをコピーできる。リンクを知る出演者はログインなしで「初回登録」「登録内容の更新」を選べる。更新はバンドを選択して名前と所属メンバーを追加・差し替え・所属解除する。初回は1〜20人、更新は0〜20人。
5. 「出演順」で順番号を入力し、Enterまたはフォーカスを外して確定する。空欄で未配置に戻る。「未配置へ」から未配置一覧へ移動できる。
6. 「手動追加」で条件の種類を選び、対象・数値などを入力する。確認欄の日本語と「必須／任意」を確認して追加する。必須は必ず守る条件、任意はできるだけ守る条件で、任意のみ優先度を選べる。チャットを使わずに追加でき、要望の原文も未入力でよい。
7. 並べ替えながら制約ごとの達成・違反・未判定を確認する。「未達成のみ」で違反と入力不備を絞り込める。未判定はこの絞り込みに含めない。
8. 必要なら「CSVを出力」で現在の出演順と未配置一覧を保存する。

作成・登録・更新はDBに保存され、再読み込み後も残る。固定サンプルの自動復元は行わない。

## URL

イベント詳細はPC（幅1280px以上）で、出演順・制約・右端のAIチャットの3列に表示する。ヘッダー以下の高さを使い、各一覧・チャット履歴は領域内でスクロールする。狭い画面では縦に並ぶ。イベント名は上部ナビゲーションに表示し、チャット入力はチャット領域の下部に置く。

| URL                            | 内容                             |
| ------------------------------ | -------------------------------- |
| `/login`                       | ワークスペースを開く             |
| `/event`                       | イベント一覧・検索・作成         |
| `/event?create=1`              | イベント一覧で作成フォームを開く |
| `/event/:eventId`              | 出演順・制約・チャット           |
| `/event/:eventId/performances` | 出演枠・所属メンバー・希望の編集 |
| `/event/:eventId/forms`        | ログイン不要の出演登録フォーム   |
| `/event/:eventId/forms/edit`   | 回答フォームのリンク・登録名簿   |
| `/event/:eventId/settings`     | イベント設定・削除               |

URLのeventIdはDBに保存されたイベントID。存在しないイベント・URLには復帰リンクを表示する。一覧が0件でも「イベントを作成」から登録できる。旧 `/forms/demo` URLは同じIDの実フォーム `/forms` へ転送する。

## データと制約の扱い

- イベント一覧・作成・設定・出演順・制約・会話・公開名簿は実APIを使う。回答フォームへの登録・所属変更は同じイベントの管理画面にも反映される。APIエラーから固定データへ切り替えない。
- 公開フォームは取得時の`updatedAt`を`expectedUpdatedAt`として送信する。競合時には入力を残し、名簿を再取得して確認してから保存する。送信中の連打・モード切替を防止する。
- 「削除」は選んだバンドからの所属解除。メンバー自体は名簿に残り、同じIDで再選択できる。他バンドの所属と元の名前は変更しない。
- 画面の部・順番号は1始まり、制約データは0始まり。「間に2組空ける」は `min_diff: 3`。間隔は現在の枠番号の差で判定し、空き枠を詰めない。
- 固定は指定位置にある有効なhardの `at_position` から導く。固定チェックを外すと、その出演枠の有効なhardの位置指定を削除する。softの位置指定や無効な条件は固定しない。
- 配置済みの出演枠は、部をまたぐ場合も固定枠を飛ばして並べ替える。移動元から移動先までの固定されていない枠（空き枠を含む）だけが順にずれ、ドラッグ中も固定枠は動かない。固定枠への直接配置は拒否する。未配置から埋まった枠へ移すと、押し出された出演枠が未配置に戻る。
- 「並べ替え」ハンドルにフォーカスし、Spaceで持ち上げ、上下の矢印で移動先を選び、Spaceで確定する。Escapeで取り消す。確定・取消後もハンドルにフォーカスが残る。番号入力でも同じ配置操作ができ、範囲外の入力は確定時に短いエラーを表示する。番号入力もEscapeで入力前の値に戻る。
- 部数は1〜8、各部は1〜20枠。縮小で外れた出演枠は未配置へ移す。固定位置がずれる変更や、制約の位置・部参照が範囲外になる変更は拒否する。無効な条件も参照を保持するため、必要なら先に編集・削除する。
- 制約に直接参照されている出演枠は削除できない。制約一覧で確認・整理してから削除する。メンバー対象の間隔条件は名簿から出演枠を集め直す。
- 達成判定は現在の配置に対するもの。対象に未配置の出演枠があれば未判定、無効なら判定対象外。ソフト条件の重み付きスコア・最適性は扱わない。
- CSVはUTF-8 BOM付き。部・順番号・出演名・メンバー・固定を出力し、未配置も末尾に含める。数式として解釈される先頭文字を含む値は文字列として出力する。

## 現在の対応範囲

公開フォームはバンド名と所属メンバーを保存する。希望・連絡先・締切・受付設定・回答数の保存は名簿APIに含まれないため、フォーム管理で未保存の設定を編集できるようには見せない。認証APIは#57/#59で接続予定で、現時点の開始ボタンは共有ワークスペースへの入口。

出演順は明示保存、制約は自動保存。チャットは保存済み履歴を復元し、送信・再試行に同じ発言IDを使う。変更案は確認・必要な設定値の選択後に保存し、計算ボタンは出演順・制約の保存後にSolverへ接続する。LLM・Solverの利用には環境ごとのAPI設定が必要。

## 確認

```sh
npm run check
npx playwright install chromium # 初回のみ
npm run test:e2e
```

ブラウザテストはポート5174でfrontendを起動し、結果を `apps/frontend/test-results/` に出力する。チャットの応答は成功・失敗ともテストで差し替え、実LLMを呼ばない。DB保存はbackendのD1結合・API契約テストとAPI用ブラウザテストで確認する。ブラウザテストでのLLM・Solver応答は差し替え、本番の外部サービス・DBは検証に使用しない。

## 出演枠の編集

「出演枠・メンバー」の各行の編集リンクは、対象バンドを選択済みの回答フォームを開く。バンド名と所属だけを保存し、既存の希望・配置・固定・制約はAPIで保持する。保存後に管理画面を開き直すと最新の名前・所属を取得できる。

## 実APIのフォーム確認

```sh
npm run test:e2e:api -- registration-api.e2e.ts
```

通常の画面テストは`npm run test:e2e`、実API・ローカルD1の確認は`npm run test:e2e:api`（専用の`.wrangler/e2e-api`を自動準備し、通常のローカルDBから分離）。テスト用の固定データは`--mode test`と`VITE_DATA_SOURCE=mock`を明示した検証環境だけで使う。`CAPTURE_FORM_SCREENSHOTS=1`をAPIテストへ付けると登録・更新フォームを再撮影できる。
