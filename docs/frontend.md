# フロントエンドの使い方

画面は同一originの実APIと、その環境のD1を使う。モック用の固定イベント・名簿や切替処理は持たない。devとmainのDBはWorkers設定で分離し、固定のイベントを画面内で生成しない。

## 起動と一通りの操作

リポジトリルートで `npm run dev` を実行し、`http://localhost:5173` を開く。

1. 「ワークスペースを開く」からイベント一覧へ入る。
2. 一覧から保存済みイベントを開くか、「イベントを作成」から新しく登録する。
3. 「フォーム管理」から出演登録フォームを開き、バンド名とメンバーを登録する。名前は1人1行で人数分を追加し、掛け持ちの人は名簿から選ぶ。同名を新しく入力した人は別IDになる。
4. 「フォーム管理」から回答フォームのURLをコピーできる。リンクを知る出演者はログインなしで「初回登録」「登録内容の更新」を選べる。更新はバンドを選択して名前と所属メンバーを追加・差し替え・所属解除する。初回は1〜20人、更新は0〜20人。
5. 「出演順」で順番号を入力し、Enterまたはフォーカスを外して確定する。空欄で未配置に戻る。「未配置へ」から未配置一覧へ移動できる。
6. 「手動追加」で条件の種類を選び、対象・数値などを入力する。確認欄の日本語と「必須／任意」を確認して追加する。必須は必ず守る条件、任意はできるだけ守る条件で、任意のみ優先度を選べる。チャットを使わずに追加でき、要望の原文も未入力でよい。
7. 並べ替えながら制約ごとの達成・違反・未判定を確認する。「未達成のみ」で違反と入力不備を絞り込める。未判定はこの絞り込みに含めない。
8. 必要なら「CSVを出力」で現在の出演順と未配置一覧を保存する。

出演順の出演名を選ぶと詳細を確認できる。編集は詳細ダイアログ内で行い、削除は確認後に実行する。出演順や制約に未保存の変更があるときは、保存するまで編集・削除を行えない。制約カードは必須・任意・無効を色でも区別し、必須違反は赤、未達成の任意制約は黄色で表示する。

作成・登録・更新はDBに保存され、再読み込み後も残る。固定サンプルの自動復元は行わない。

## URL

イベント詳細はPC（幅1280px以上）で、出演順・制約・右端のAIチャットの3列に表示する。幅1280px未満では、画面下部の「出演順／制約／AIチャット」タブで1パネルずつ切り替える。ヘッダーと下部タブの間の高さを使い、各一覧・チャット履歴は領域内でスクロールする。チャット入力はチャット領域の下部に置く。

タブを切り替えても未保存の出演順・入力中のチャット本文・制約の絞り込みを保持する。チャットの「未達成の条件を確認」は制約タブへ移り、未達成のみを表示する。タブは左右キー・Home・Endでも選択できる。出演順の表は横にスクロールでき、狭い画面で上部の操作ボタンが収まらない場合も、ボタン列だけ横にスクロールする。ボタン内の文字やボタン列は折り返さない。

スマートフォンではヘッダーの利用者名を省略し、ログアウトはアイコンで表示する。長いイベント名は上部ナビゲーションで省略表示し、設定画面で全文を確認できる。通知は下部タブの上に表示し、画面下端のセーフエリア分の余白を取る。

| URL                          | 内容                             |
| ---------------------------- | -------------------------------- |
| `/login`                     | ワークスペースを開く             |
| `/event`                     | イベント一覧・検索・作成         |
| `/event?create=1`            | イベント一覧で作成フォームを開く |
| `/event/:eventId`            | 出演順・制約・チャット           |
| `/event/:eventId/forms`      | ログイン不要の出演登録フォーム   |
| `/event/:eventId/forms/edit` | 回答フォームのリンク・登録名簿   |
| `/event/:eventId/settings`   | イベント設定・削除               |

URLのeventIdはDBに保存されたイベントID。存在しないイベント・URLには復帰リンクを表示する。一覧が0件でも「イベントを作成」から登録できる。旧 `/forms/demo` URLは同じIDの実フォーム `/forms` へ転送する。

## データと制約の扱い

- イベント一覧・作成・設定・出演順・制約・会話・公開名簿は実APIを使う。回答フォームへの登録・所属変更は同じイベントの管理画面にも反映される。APIエラーから固定データへ切り替えない。
- 公開フォームは取得時の`updatedAt`を`expectedUpdatedAt`として送信する。競合時には入力を残し、名簿を再取得して確認してから保存する。送信中の連打・モード切替を防止する。
- 「削除」は選んだバンドからの所属解除。メンバー自体は名簿に残り、同じIDで再選択できる。他バンドの所属と元の名前は変更しない。
- 画面の部・順番号は1始まり、制約データは0始まり。「間に2組空ける」は `min_diff: 3`。空き枠は画面内の表示で、番号・制約評価は空き枠を除く実際の出演順を使う。DBの部内orderは未設定位置の欠番を保持する。
- 固定は指定位置にある有効なhardの `at_position` から導く。固定チェックを外すと、その出演枠の有効なhardの位置指定を削除する。softの位置指定や無効な条件は固定しない。
- 配置済みの出演枠は移動先へ挿入し、部内の実際の出演順を詰め直す。固定枠への直接配置や、他の固定枠の絶対位置が変わる移動は拒否する。未配置からの追加も同じ条件で検証する。
- 「並べ替え」ハンドルにフォーカスし、Spaceで持ち上げ、上下の矢印で移動先を選び、Spaceで確定する。Escapeで取り消す。確定・取消後もハンドルにフォーカスが残る。番号入力でも同じ配置操作ができ、範囲外の入力は確定時に短いエラーを表示する。番号入力もEscapeで入力前の値に戻る。
- 部数は1〜8、各部は1〜20枠。縮小で外れた出演枠は未配置へ移す。固定位置がずれる変更や、制約の位置・部参照が範囲外になる変更は拒否する。無効な条件も参照を保持するため、必要なら先に編集・削除する。
- メンバー対象の間隔条件は名簿から出演枠を集め直す。バンド本体の削除は出演順の出演名から開く詳細ダイアログで行う。対象名を確認して削除し、メンバー名簿・他バンドの所属は残し、空いた出演枠を未設定のまま残す。制約に参照されていても削除でき、このバンドの希望から作られた制約は一緒に削除し、それ以外の制約は残す。
- 達成判定は現在の配置に対するもの。対象に未配置の出演枠があれば未判定、無効なら判定対象外。ソフト条件の重み付きスコア・最適性は扱わない。
- CSVはUTF-8 BOM付き。部・順番号・出演名・メンバー・固定を出力し、未配置も末尾に含める。数式として解釈される先頭文字を含む値は文字列として出力する。

## 現在の対応範囲

公開フォームはバンド名と所属メンバーを保存する。希望・連絡先・締切・受付設定・回答数の保存は名簿APIに含まれないため、フォーム管理で未保存の設定を編集できるようには見せない。削除が失敗した場合は確認ダイアログ内にエラーを表示する。競合時は「最新の状態を取得」で一覧を更新し、再度対象を確認する。送信中は二重実行・閉じる操作を抑止する。

認証APIは#57/#59で接続予定で、現時点の開始ボタンは共有ワークスペースへの入口。

出演順は明示保存、制約は自動保存。チャットは保存済み履歴を復元し、送信・再試行に同じ発言IDを使う。変更案は確認・必要な設定値の選択後に保存し、計算ボタンは出演順・制約の保存後にSolverへ接続する。並べ替え案は確認モーダルを開き、AIの説明・Solverで調整した場合の注記・変更前／変更後の切り替えと再生で各出演枠が滑って移動するアニメーション（開いた時は変更前のまま止める。移動した枠の色付けと移動数。動きを減らす設定では切り替えのみ）・必須条件の違反と理由・新たに満たせなくなる／満たせる任意条件を表示する。保存すると出演順をすぐ保存し、出演順の表でも各行が元の位置から新しい位置へゆっくり移動し、移動した行を一時的に色付けする（手動のドラッグには影響しない）。破棄すると並びを変えない。提案後にイベントが更新されていれば保存しない。LLM・Solverの利用には環境ごとのAPI設定が必要。

## 確認

```sh
npm run check
npx playwright install chromium # 初回のみ
npm run test:e2e
```

ブラウザテストはポート5175でfrontend、8789でWorkersを起動し、専用ローカルD1（`.wrangler/e2e-api`）を自動準備する。結果は `apps/frontend/test-results/` に出力する。登録・更新・並べ替え・制約の保存を実APIとDBで確認する。外部LLM・Solver応答と意図的な通信失敗はテスト内で差し替え、本番の外部サービス・DBは検証に使用しない。

## 出演枠の編集

出演順の出演名から開く詳細ダイアログでバンド名と所属メンバーを編集する。保存後は出演順を再取得し、ページ遷移せず最新の名前・所属を表示する。既存の希望・配置・固定・制約はAPIで保持する。

## 実APIのフォーム確認

```sh
npm run test:e2e:api -- registration-api.e2e.ts
```

`npm run test:e2e`と`npm run test:e2e:api`は同じ実API・専用ローカルD1のテストを実行する。テストの入力例は単体テストまたは専用DBへの明示登録にだけ使い、アプリへ組み込まない。`CAPTURE_FORM_SCREENSHOTS=1`をAPIテストへ付けると登録・更新フォームを再撮影できる。

実Solverと専用D1を含めたブラウザ検証は `npm run test:e2e:solver` で実行する。[準備・確認範囲](setup.md#実solverを含めたe2e)を参照。`count`の実計算は未対応（#75）。

## 部数・各部のバンド数（#91）

イベント作成ダイアログで部数と各部のバンド数を設定する。出演順パネル上部には「保存」「自動生成」「CSVを出力」「ライブ情報の編集」を並べる。ライブ情報の編集は部構成専用で、「適用」でローカル反映、「保存」で出演順とともにDBへ保存する。「キャンセル」では変更しない。

部数は1〜8、各部は1〜20組、新しい部は4組。枠を縮めると、対象の末尾・削除した部のバンドは未配置に戻す。固定・既存制約が無効になる変更は拒否する。APIモードのバンド移動は部境界を固定して順送りし、設定枠数を増やさない。未配置バンドの挿入では空き枠まで順送りし、空きがなければ末尾が未配置になる。

設定枠数は再取得・Solver結果でも維持する。登録数が不足していても生成でき、空き枠を残す。枠数超過分は未配置として表示する。空き枠はAPIモードで採番しない。
